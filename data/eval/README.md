# 矛盾提取评测集

## 文件

| 文件 | 用途 |
|---|---|
| `requirements.json` | 30 条主评测集，覆盖机械 / 电子 / 结构 / 工艺，用于验收 |
| `holdout.json` | 10 条留出集，在主要调参之后新建，用于估计泛化 |
| `last_run.json` | 最近一次主评测结果（git 忽略） |
| `last_holdout.json` | 最近一次留出集结果（git 忽略） |

## 标注约定

- **改善参数**取“为了达到目的而直接改变/提升的那个参数”，目的本身不取。
  例如“提高传送带速度以增加产能”，改善参数是 `速度`，不是 `生产率`。
- **恶化参数**取“因此直接受损的参数”。
- 使用 39 个标准参数名，不带编号。
- 对确实存在两种合理解释的样本，用 `accept_improve` / `accept_worsen` 列出可接受答案：
  - `S03`：梁截面体积可归为运动/静止物体的体积；
  - `P02`：焊接热影响区可归为温度或形状。

## 运行

```bash
# 主评测集（验收）
python scripts/evaluate_extraction.py

# 留出集（泛化）
python scripts/evaluate_extraction.py --file data/eval/holdout.json --output data/eval/last_holdout.json
```

评测直接调用 `llm_client`，不走 HTTP，也不会写入历史记录。

## 结果解读

- 30 条主评测集：100%（改善参数 100%，恶化参数 100%）。
  但该集合在开发过程中用于定位错例、补充同义词，**不能当作泛化准确率**。
- 10 条留出集：40%（qwen2.5:3b，两阶段提取 + 同义词映射）。
  这更接近 3B 模型面对新表述时的真实水平。

结论：3B 模型在“把自由表述映射到 39 个标准参数”这一步仍是瓶颈。
若要把泛化准确率稳定做到 80% 以上，优先换用 qwen2.5:7b/14b 或更大的模型，
其次才是继续扩充同义词表；单靠同义词表只能覆盖已见过的说法。
